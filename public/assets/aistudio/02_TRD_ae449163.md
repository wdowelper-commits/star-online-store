## 2. Architecture Overview

```
Browser (React SPA)
    ↓ HTTPS
Cloudflare Workers & Pages (CDN + Edge)
    ↓ VITE_ env vars
Supabase (PostgreSQL + Auth + Storage)
    ├── Auth: Email/Password + Google OAuth
    ├── Database: PostgreSQL with RLS
    └── Storage: Product images, seller logos
```

**Pattern:** Client-side SPA. All DB operations go directly from React → Supabase JS client using anon key + RLS policies. No custom backend server.

## 5. Supabase Integration Strategy

### 5.1 Client Setup

```typescript
// src/lib/supabaseClient.ts
import { createClient } from '@supabase/supabase-js'

const supabaseUrl = import.meta.env.VITE_SUPABASE_URL
const supabaseAnonKey = import.meta.env.VITE_SUPABASE_ANON_KEY

export const supabase = createClient(supabaseUrl, supabaseAnonKey)
```

**Never hardcode keys.** Keys come only from `.env` file (local) and Cloudflare environment variables (production).

### 5.2 Auth Integration

- `supabase.auth.onAuthStateChange()` listened in `App.tsx`
- User role stored in `profiles` table (`role` column: `customer | seller | admin`)
- After login: fetch profile → check role → redirect accordingly
- Google OAuth: Supabase Google provider enabled

### 5.3 Storage

- Bucket: `product-images` (public read, authenticated write)
- Bucket: `seller-assets` (public read, authenticated write)
- Upload path: `product-images/{seller_id}/{product_id}/{filename}`
- Public URL via `supabase.storage.from('product-images').getPublicUrl(path)`

## 6. Authentication Approach

| Method | Implementation |
|--------|---------------|
| Email/Password | Supabase Auth built-in |
| Google OAuth | Supabase Google provider |
| Session | Supabase handles JWT, persisted in localStorage |
| Role check | `profiles.role` column checked after auth |
| Protected routes | `<ProtectedRoute>` component wraps private pages |
| Role guard | `<RoleGuard allowedRoles={['admin']}>` for role-specific pages |

**Admin setup:** First admin created manually in Supabase dashboard by setting `profiles.role = 'admin'`.

---

## 7. Security Requirements

- **RLS enabled** on all tables — no table has open access
- Anon key in frontend — never service-role key
- Sellers can only read/write their own products and orders (RLS by `seller_id = auth.uid()`)
- Customers can only read their own orders and wishlist (RLS by `customer_id = auth.uid()`)
- Admin role bypasses RLS via Supabase `is_admin` check or separate policy
- Storage bucket policies: authenticated users can upload to their own folder only
- Input validation: Zod schemas on all forms
- No sensitive data in URL params

---

## 8. API / Service Requirements

All operations via Supabase JS client:
- **Auth:** signUp, signInWithPassword, signInWithOAuth (Google), signOut, resetPasswordForEmail
- **Products:** select with joins (category, seller profile), insert, update, delete
- **Orders:** insert order + order_items in transaction, update status
- **Coupons:** validate (check expiry, usage, min order), apply (decrement usage_count)
- **Storage:** upload, getPublicUrl, remove
- **Realtime (optional):** order status updates (nice-to-have)

## 11. Performance Considerations

- Lazy load React routes (`React.lazy + Suspense`)
- Product images: use Supabase Storage CDN URLs
- Paginate product lists (20 per page)
- Zustand for lightweight global state (no Redux overhead)
- Tailwind CSS purging in production build
